# 视觉质量门槛（中文参考）

本文件是 [`quality-gate.md`](quality-gate.md) 的中文阅读版。英文文件是执行规范的唯一来源；如果两者出现差异，以英文文件为准。

## 默认通过条件

每个维度按 1–10 分评分，等权换算为 100 分。总分至少 `80/100`，每个维度至少 `7/10`，且没有明显的视觉或响应式缺陷。

这些分数是帮助比较 Before / After 的判断工具，不是客观的审美测量。

## 七个维度

| 维度 | 要问的问题 |
| --- | --- |
| 层级 | 用户能否在三秒内看出最重要的信息或动作？ |
| 构图 | 整个画面是否有明确结构，而不是组件堆叠？ |
| 排版 | 字号、字重、行长和对比度是否形成真正的层级？ |
| 间距与密度 | 留白和间距是否在组织内容，而不是机械地到处加 padding？ |
| 色彩与效果 | 颜色、阴影、渐变和模糊是否承担了有意义的结构作用？ |
| 特异性 | 这个界面是否像为当前产品做的，而不是换文案就能变成任意 SaaS？ |
| 响应式完整性 | 移动端是否重新编排，而不是把桌面端简单压缩？ |

## 迭代顺序

先看整个画面，再选 1–3 个最大杠杆问题。优先处理：

1. Hero 或首屏构图
2. 信息层级与主动作
3. 内容宽度、对齐和区块节奏
4. 展示/正文排版关系
5. 重复卡片和装饰性 chrome
6. 移动端重新编排

不要因为 scanner 报告了渐变、圆角或阴影，就机械地删除它们。它们可以是合理的设计工具；真正需要避免的是无理由、重复、默认式使用。

## 输出必须包含

- 视觉层面实际改变了什么
- 最终评分和是否通过
- 实际渲染并检查过的 viewport
- 剩余的视觉风险或未验证区域
