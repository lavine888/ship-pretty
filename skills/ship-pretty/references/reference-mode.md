# Reference Gate Mode

Use this when the user supplies one or more visual references.

## First classify the task

Determine whether the user wants:

1. **quality anchoring** — “make mine feel this polished”;
2. **style direction** — “use this visual language”;
3. **structural inspiration** — “I like how this page organizes information”;
4. **pixel parity** — reproduce a provided design accurately.

Do not assume pixel parity unless the request clearly requires it.

## Extract principles before editing

For each reference, identify:

- dominant composition model;
- display/body type relationship;
- content density;
- spacing rhythm;
- surface hierarchy;
- corner/radius behavior;
- border and shadow discipline;
- accent-color scarcity or abundance;
- image/illustration role;
- CTA hierarchy;
- mobile recomposition if available.

Then find the principles shared across references. Shared principles are a stronger anchor than one-off decorative details.

## Build a reference brief

Keep it short. Example:

> References share editorial typography, sparse surfaces, asymmetric hero composition, one saturated accent, and high information density below the fold. Their polish comes from type and spacing rather than glow or card chrome.

Use this brief to judge subsequent screenshots.

## Avoid imitation traps

Do not copy:

- logos;
- proprietary illustrations;
- branded icons;
- distinctive trade dress when the user is only asking for inspiration;
- exact marketing copy.

Transfer principles, not identity.

## Compare on the right axes

Bad comparison:

> “Reference has blue, ours has purple.”

Better comparison:

> “Reference reserves saturated color for one decisive action; ours spreads accent color across five unrelated surfaces, so nothing wins attention.”

## If references conflict

Prefer the subset that best matches the user's stated product goal. If the user supplied incompatible references without a stated priority, infer a coherent intersection instead of producing a collage of styles.
